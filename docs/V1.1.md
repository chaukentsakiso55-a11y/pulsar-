# Pulsar AI v1.1 — Tools + Document RAG

Pulsar AI v1.1 closes two capability gaps: safe server-side tools and direct document ingestion.

## Safe tools

New authenticated endpoints:

- `GET /v1/tools` — list built-in tools.
- `POST /v1/tools/call` — execute an approved tool.

Built-ins in v1.1:

- `calculator` — bounded arithmetic/scientific expressions using an AST whitelist (no Python `eval`, shell, file writes, or network access).
- `knowledge_search` — searches Pulsar's private knowledge store using the existing FTS5/BM25 retriever.

Chat and Responses requests can set `"enable_tools": true`. When the selected OpenAI-compatible backend supports native function calling, Pulsar advertises its safe tool schemas, executes up to three approved calls, injects the results as trusted tool context, and continues normal Pulsar Max reasoning. Backends without native tool calling remain compatible and simply return no tool calls.

vLLM and llama.cpp both support OpenAI-style function/tool calling, so they can participate in this path when configured correctly.

## Document ingestion

New admin endpoint:

`POST /admin/knowledge/file`

It accepts multipart uploads up to 10 MB, extracts text, chunks it with overlap, and stores the chunks in Pulsar's RAG database.

Supported inputs include PDF, Markdown, text, CSV, JSON, XML/HTML, logs, configuration files, and common source-code formats such as Python, JavaScript/TypeScript, Kotlin, Java, C/C++, Rust, Go, SQL, shell and PowerShell.

PDF extraction uses `pypdf`. Scanned/image-only PDFs still need OCR before Pulsar can ingest their text.

## Compatibility and security

- Existing `/v1/chat/completions` and `/v1/responses` behavior remains unchanged unless `enable_tools` is explicitly enabled.
- Existing API-key behavior for `/v1/models` and `/v1/usage` is preserved.
- The new direct tool endpoints require the `tools` API-key permission.
- The Windows launcher now creates keys with `tools` permission by default.
- No shell execution, arbitrary URL fetching, device control, or filesystem-write tool is enabled by default.
