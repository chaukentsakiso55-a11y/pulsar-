# Pulsar AI v1.2 — Web Research, Embeddings & Semantic Memory

Pulsar AI v1.2 closes three major capability gaps while preserving the v1.1 API surface.

## Web research

Pulsar can use a **SearXNG-compatible JSON Search API** as a read-only public web research source.

Configure locally in `.env`:

```env
PULSAR_WEB_SEARCH_URL=http://127.0.0.1:8080
PULSAR_WEB_SEARCH_TIMEOUT=15
PULSAR_WEB_SEARCH_SAFESEARCH=1
```

New authenticated endpoint:

```text
POST /v1/research/search
```

Chat and Responses requests may also opt in:

```json
{
  "model": "pulsar-max",
  "input": "What changed recently in this technology?",
  "enable_web_search": true
}
```

Proactive web research requires the `research` API-key permission. Pulsar inserts result titles, URLs and snippets as **untrusted external context** and warns the model not to follow instructions embedded in snippets.

The built-in `web_search` tool becomes available when a search service is configured. It is search-only: Pulsar does not automatically open arbitrary result URLs, execute scripts, or write files.

## Embeddings

New OpenAI-style endpoint:

```text
POST /v1/embeddings
```

Example:

```json
{
  "model": "pulsar-embed",
  "input": ["gravity and orbital motion", "photosynthesis"]
}
```

Pulsar supports an external OpenAI-compatible embedding server such as a compatible vLLM deployment:

```env
PULSAR_EMBEDDINGS_BASE_URL=http://127.0.0.1:8001/v1
PULSAR_EMBEDDINGS_MODEL=intfloat/e5-small-v2
PULSAR_EMBEDDINGS_API_KEY=
```

If no external embedding server is configured, Pulsar automatically uses `pulsar-embed-lite`, a deterministic offline fallback vectorizer. It is useful for local development and lightweight similarity, but a dedicated embedding model gives substantially better semantic quality.

## Semantic memory

Pulsar now stores semantic memories in a separate SQLite table with vector, model and dimension metadata.

New endpoints:

```text
POST /v1/memory
POST /v1/memory/search
```

When a chat request includes `conversation_id`, Pulsar can:

1. keep the existing recent chronological conversation memory;
2. retrieve semantically related older memories;
3. store the latest user and assistant messages as semantic memories after the response.

This is enabled by default and can be disabled:

```env
PULSAR_ENABLE_SEMANTIC_MEMORY=false
```

Pulsar ignores stored vectors whose dimensions no longer match the currently configured embedding model. This allows changing embedding backends without corrupting existing memory or crashing retrieval.

## New API-key permissions

v1.2 adds:

- `embeddings`
- `research`
- `memory`

The Windows launcher creates new client keys with these permissions plus the existing chat/model/tool permissions.

## Windows configuration

Run `PULSAR.bat` and choose:

```text
[14] Configure Web Research + Embeddings
```

The wizard writes provider/search settings only to the local `.env`. Real API keys are not committed to GitHub.

## Security boundaries

- Web research is opt-in for chat/Responses requests.
- Search results are treated as untrusted external data.
- Search result URLs are restricted to HTTP/HTTPS.
- No arbitrary browser navigation or page execution is included.
- No shell, device-control, or filesystem-write tool is added.
- Embedding/search secrets remain in `.env`, which is Git-ignored.
